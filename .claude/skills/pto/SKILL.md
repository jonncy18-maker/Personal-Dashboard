## PTO Planner

**PTO Planner — no AI, a self-set budget (never accrual), and two ledgers that never mix in their underlying accounting.** Built 2026-08-08 per `PTO_BUILD_PLAN.md` (deleted after build; its content lives on in the 2026-08-08 ROADMAP.md entries) — pure date math + CRUD, no model anywhere in it. A `pto_settings.annual_budget` (default 25) is John's own editable target, not an employer balance — CrossCountry's PTO is unlimited, so there is no accrual math, ever. Days auto-derive from real trips (`status` upcoming/past; wishlist never counts): weekdays in the trip's range minus `pto_holidays`, split taken/planned around today. A trip's `pto_days_override`/`pto_exempt` (migration 016) **sticks once set — auto math never overwrites it**, same discipline as `trips.image_source = 'manual'`. The **banked-holiday ledger** (`worked` toggle on a holiday row → earned; a `banked_spend` entry → spent) is computed fully separately from `taken`/`planned`/`left` — a spent banked day overlapping a trip is John's call via that trip's override, never an automatic offset. All of this lives in one pure, DB-free `lib/pto.js` shared by the server (`/api/pto/*`, `home-summary`) and the client (`PtoPanel.jsx`'s sandbox calculator + saved-scenario costs), so the math is never duplicated. A **simulation layer** (dated-wishlist what-ifs, a sandbox calculator, saved named scenarios) sits on top of the real ledger, always phrased "would leave X" — **never** written into `taken`/`planned`/`left`. A year switcher covers the current year plus two ahead; a future year with no holidays entered computes without exclusions and says so honestly rather than pretending the count is final. Not a 7th domain — lives on `/travel` (`PtoPanel.jsx`) plus one "N PTO left" line on Home's Travel card, no new route, no new Home card.

**The glance strip's headline is a net figure, blending banked in only when John explicitly opts in (migration 024).** `pto_settings.use_banked_for_shortfall` (default `false`) is a deliberate, John-controlled toggle — living in the panel's 4th sub-tab, **Planning** (after Trips / Log / Simulate) — that decides whether `lib/pto.js`'s `netPtoLeft()` adds the banked ledger's `available` count into the number shown as the headline figure. This is display-only: `left`/`taken`/`planned` and the banked ledger are still computed exactly as before, fully separately, in `ptoSummary()` — the toggle never touches that accounting, it only decides what `/api/pto`'s `net` field (and therefore the glance strip) equals. The breakdown behind the headline (raw PTO left, taken/planned, banked available, and whether the toggle is on) sits in a popover — hover reveals it on desktop, tapping the figure toggles it on mobile (`@media (hover: hover)` gates the CSS-only hover reveal so touch devices fall back to the click state cleanly).
